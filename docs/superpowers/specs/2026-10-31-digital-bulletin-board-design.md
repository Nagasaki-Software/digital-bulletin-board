# デジタル掲示板 設計書

作成日: 2026-10-31 / 状態: レビュー済み（配色の切り替え・連絡事項の行数・ジャンルの扱いの変更を反映。実装計画は別ファイル）

## 1. 目的と利用者

工場などで「本日の作業内容」を掲示しているホワイトボードを、70インチ程度のタッチパネルモニタに置き換える電子掲示板。

- 見る人: 現場の作業者全員（モニタの前）
- 入力する人: 作業の取りまとめ担当者・作業者（モニタのタッチ操作、または社内LANの他のPC）
- 画面案: `画面案.pdf`（作者が手元で作った画面案）（本設計はこれに従う）
- デザイン案: Claude の Design「デジタル掲示板 画面デザイン案」（案A 明るい・案B 暗い・案C 元の案に近い）。**採用は案Aと案Bの2つで、設定で切り替える**（4.7）。案Cは使わない
- 見た目・操作は `apps/equipment-inspection` に似せる（メイリオ優先、タッチ向けの大きなボタン、PDF表示は同アプリの PDF.js を流用）

成功の条件: ホワイトボードを使わずに、朝の入力だけで1日の作業予定・連絡事項・災害事例が掲示できること。

## 2. 全体構成

- 場所: `apps/digital-bulletin-board/`（小文字ケバブケース。1アプリ1フォルダ1リポジトリ）
- 技術: Flask + waitress（Webサーバー）、SQLite（標準ライブラリ `sqlite3`）、ブラウザ画面（HTML/JS/CSS）
- 1台のPCがサーバーになる。モニタも他のPCも、同じアドレスをブラウザで開く
- ポート: **5100 固定**（equipment-inspection が 5000 を使うため。同じPCで両方動かしても衝突しない）
- サーバーは `0.0.0.0` で待ち受ける（他のPCから開くため）。ログイン認証は付けない（1台・社内LAN前提）

### フォルダ構成（予定）

```
digital-bulletin-board/
├── app.py                 … ルート（URL）定義
├── board_db.py            … SQLite の読み書き（前日の引き継ぎ・週の判定を含む）
├── masters.py             … 登録リスト(CSV)・休日・災害事例ファイルの読み込み
├── config.json            … 設定（Git管理外。無ければ既定で起動）
├── requirements.txt
├── 起動.bat / 初回セットアップ.bat
├── data/
│   ├── companies.csv      … 所属・会社名／氏名
│   ├── leaders.csv        … 責任者（会社名・責任者名・内線・外線）
│   ├── works.csv          … 作業内容
│   ├── genres.csv         … 作業ジャンル（表示順）
│   ├── times.csv          … 就業予定の時刻の候補
│   ├── custom_holidays.csv… 会社の休日（date,name）
│   └── board.db           … SQLite（Git管理外）

```

1ファイルが1000行を超えたら、完了報告時にモジュール分割を提案する。

## 3. 画面構成（1画面。画面案どおり）

| 位置 | 内容 |
|---|---|
| 左上 | 日付（例: 2026年11月2日（月）） |
| 右上 | 会社名（config の `company_name`。例: サンプル工業(株)）と、歯車ボタン |
| 左 | 連絡事項（3行分の高さ。増えたら枠の中でスクロール）／本日の作業予定（表） |
| 右上段 | 災害事例の自動再生枠（A4横の縦横比 297:210） |
| 右中段 | 作業ジャンルのチェック（genres.csv の数だけ。多いときは折り返し、2行を超えたら枠の中でスクロール） |
| 右下段 | 今週の休日出勤予定（表）／文書ボタン |

- 文字・表・ボタンは、画面の幅に合わせて拡大縮小する（フルHD・4Kで崩れない）。基準は 1920×1080。
- 表は偶数行を薄い灰色にし、見出し行は固定、行数が多いときは表の中だけ縦スクロール。
- 0時を過ぎたら、自動で新しい日の表示に切り替わる。
- 配色は「明るい（案A）」「暗い（案B）」の2種類を CSS 変数で切り替える（4.7）。災害事例の枠（A4の用紙）は、どちらの配色でも白い紙の色のまま。

## 4. 機能

### 4.1 入力の基本

- 欄をタップすると、大きなボタンの選択パネルが開き、登録済みの候補から選ぶ（ドロップダウンの代わり）。
- 登録リストに無い値は入力できない。**例外は連絡事項のみ（自由入力）**。
- 選んだ時点で即保存する（「保存」ボタンは無い）。

### 4.2 連絡事項

- 日付ごとに、最初は空の3行。自由入力（Windows のタッチキーボードを想定。実機で出るか **未確認**。出ない場合はアプリ内キーボードに切り替える）。
- **常に3行分の高さで表示し、4行目以降は枠の中だけを縦にスクロールする。**
- 編集のとき「＋ 連絡事項を追加」で行が増える。4行以上あるときだけ、各行に✕が出て削除できる（**3行未満にはならない**）。
- 各行に「赤字」スイッチ。オンの行は赤字で表示する。
- 前日からは**引き継がない**（毎日空欄から始まる）。※想定。違っていれば変更する。

### 4.3 本日の作業予定

- 列: 所属・会社名／責任者／作業内容／就業予定。
- 就業予定は「開始時刻」と「終了時刻」を別々に選ぶ。候補は `times.csv`。表示は `9:00～15:00`。
- **会社を選ぶと、責任者の候補はその会社の責任者（leaders.csv の会社名が一致する人）だけになる。** 会社を変えたら責任者は空にする。責任者が未登録の会社は責任者が空欄のまま。
- 責任者の名前の下に、連絡先を小さく表示する。内線・外線のうち入っているほうを表示し、両方入っていれば両方（例: `内線 1234` / `外線 03-1234-5678`）。
- 行の追加・削除ができる。**途中の行を削除したら、下の行が上に詰まる。**
- 各行に ▲▼ ボタン。押すと1つ上／下の行と入れ替わる。
- **前日の内容の引き継ぎ**: その日の初回アクセス時に、その日の作業予定がまだ作られていなければ、「直近で作業予定がある日」の行をコピーして始める（休日をまたいでも直近の日を使う）。コピーしたあとに全行を削除した日は、再コピーしない（日付ごとに「作成済み」の印を持つ）。

### 4.4 今週の休日出勤予定

- 列: 日付／氏名・会社名／作業内容／就業予定。
- 「今週」は **月曜〜日曜**。月曜になると前の週の行は表示されず、空欄になる（データはDBに残る）。
- 行は日付順に自動で並ぶ（▲▼は無い）。行の追加・削除、行が多いときのスクロールは作業予定と同じ。
- **日付の選択肢は、今週のうち休日の日だけ**（土日・祝日・会社の休日）。表示は `11/3(火・文化の日)` のように休日名を付ける。土曜は青、日曜・祝日・会社の休日は赤。
- 祝日は `jpholiday` で自動判定、会社の休日は `data/custom_holidays.csv`（equipment-inspection と同じ形式）。会社の休日の登録漏れがあると、その日は選べない。
- 氏名・会社名の候補は companies.csv、作業内容は works.csv、時刻は times.csv。

### 4.5 作業ジャンルと災害事例の自動再生

- ジャンルのチェックは日付ごとに保存し、前日のチェックを引き継ぐ（作業予定と同じ扱い）。
- **ジャンルの追加・名前の変更・並べ替えは `data/genres.csv`（Excel）で行う。画面からは変えない。** 名前を変えたら、災害事例PDFのファイル名の先頭も同じに直す。ジャンルが増えたら、チェックの枠は折り返す（2行を超えたら枠の中でスクロール）。
- 災害事例は `accident_cases/` のPDF。**ファイル名の先頭（最初の `_` より前）がジャンル名**（例: `溶接作業_事例A.pdf`）。
  - 複数ジャンルに当てはまる事例は `＋` でつなぐ（例: `溶接作業＋高所作業_事例A.pdf`）。どれかがチェックされていれば再生し、重複しては出さない。
  - genres.csv に無いジャンル名のファイルは再生しない。
- 再生順: genres.csv の並び順、同じジャンルの中はファイル名順。最後まで行ったら先頭に戻る。
- 1枚の表示秒数は config の `accident_seconds`（既定 15秒）。タップ・左右スワイプで手動送りでき、手動で送ったら表示秒数を数え直す。
- PDFが複数ページなら、1ページを1枚として順に表示する。A4横の枠に収める（縦向きのファイルは左右に余白が出る）。
- チェックが1つも無い、または該当ファイルが無いときは、枠に「作業ジャンルを選ぶと災害事例が表示されます」（該当ファイルが無いときは「該当する災害事例がありません」）と出す。

### 4.6 文書ボタン（右下）

- config の `documents.buttons`（最大5つ。ボタン名とフォルダ）。既定は「文書1・文書2・文書3」の3つ。
- ボタンを押す → フォルダ内のPDFの一覧 → 選ぶとPDF閲覧画面（ピンチ・ホイールで拡大）。
- 「閉じる」ボタン、または `documents.idle_return_seconds`（既定 120秒）操作が無いと、掲示板に戻る。

### 4.7 編集ロックと設定メニュー

- 右上の歯車ボタンから設定メニューを開く。設定は「**編集ボタン: あり／なし**」と「**配色: 明るい／暗い**」の2つ。
- **あり**: 通常は閲覧のみ（欄をタップしても開かない）。「編集」ボタンを押すと入力できる。`edit_lock_seconds`（既定 60秒）操作が無いと、自動で閲覧に戻る。
- **なし**: 常に入力できる。
- 設定は**端末（ブラウザ）ごと**にブラウザへ保存する（モニタを「あり」にしても他のPCは変わらない）。初期値は「なし」。ブラウザの保存データを消すと初期値に戻る。
- 配色の初期値は config の `default_theme`（既定 `light`）。端末で選んだ配色は、その端末のブラウザに保存され、以後はそれが優先される。
- 暗証番号は付けない。歯車から「なし」に切り替えられるため、これは**誤操作防止であって防犯ではない**。サーバー側でも入力を拒否しない。

### 4.8 待機画面

- 毎日、`standby.start`（既定 18:00）〜 `standby.end`（既定 翌 7:30）は、時計（時刻と日付）だけの画面に切り替える。土日祝も、この時刻の間以外は通常表示。
- 触ると掲示板に戻り、操作が無いまま `standby.wake_idle_seconds`（既定 300秒）続くと、時刻の間なら再び待機画面に戻る。※想定。
- 時刻は閲覧しているPCの時計で判定する。

### 4.9 同時入力と更新

- 同じ欄を複数人が触った場合は、**あとから保存した内容が残る**。
- 画面は 3秒ごとにサーバーへ問い合わせて更新する（変更が無ければ描き直さない）。**選択パネルを開いている間・入力中は更新で閉じない。**
- 登録リスト（CSV）は、更新のたびに変更時刻を見て、変わっていたら読み直す。壊れている・見つからないときは、画面に警告を出す（掲示は止めない）。

## 5. データ

### 5.1 登録リスト（`data/*.csv`。UTF-8 BOM付き。Excelで編集）

| ファイル | 列 | 使う場所 |
|---|---|---|
| companies.csv | `name` | 作業予定の所属・会社名、休日出勤の氏名・会社名 |
| leaders.csv | `company,leader_name,ext,outside` | 作業予定の責任者（会社で絞る）と連絡先 |
| works.csv | `name` | 作業内容（両方の表） |
| genres.csv | `name` | 作業ジャンル（並び順も兼ねる） |
| times.csv | `time` | 就業予定の開始・終了。無ければ 6:00〜22:00 の30分刻みで自動生成して作る |
| custom_holidays.csv | `date,name` | 会社の休日 |

同梱するサンプルは架空のもの（サンプル工業(株) など）。

### 5.2 SQLite（`data/board.db`、WAL モード）

- `days(date PRIMARY KEY, schedule_initialized, genres_initialized, notices_initialized)` … 引き継ぎ・初期化済みの印
- `notice_rows(id, date, position, text, red)` … 連絡事項（その日の初回アクセスで空の3行を作る。3行未満にはならない）
- `schedule_rows(id, date, position, company, leader, work, start_time, end_time)` … 本日の作業予定
- `holiday_rows(id, date, person, work, start_time, end_time)` … 休日出勤（表示は今週分のみ）
- `checked_genres(date, genre)` … 作業ジャンルのチェック
- 画面が使う「リビジョン番号」を1つ持ち、変更のたびに増やす（3秒ごとの更新で、変化の有無だけ先に確認するため）。

### 5.3 設定（`config.json`。Git管理外。無ければ既定で起動）

`company_name` / `default_theme` / `accident_folder` / `accident_seconds` / `documents.buttons` / `documents.idle_return_seconds` / `edit_lock_seconds` / `standby.start` / `standby.end` / `standby.wake_idle_seconds`

設定画面は作らない（直接編集。変更後はサーバー再起動）。

## 6. 外部部品

- **PDF.js**: equipment-inspection の `static/pdfjs/` をコピーして使う（新規インストールではない）。ライセンス表示（`THIRD_PARTY_NOTICES.md`）も引き継ぐ。
- **jpholiday**（祝日判定）: equipment-inspection で使用中だが、このアプリでは新規追加になる。**インストール前に package-security-scan でスキャンし、承認を得る。**
- そのほか: flask, waitress（equipment-inspection と同じ）、pytest（テスト用）。

## 7. 日本語Windows・省メモリの注意

- `open()` には必ず `encoding` を明示する。CSVは `utf-8-sig`。
- パスに日本語・空白があっても動くこと（災害事例・文書フォルダ）。
- 常駐するのは Flask(waitress) 1プロセスのみ。更新の問い合わせは軽量なJSONだけにする。

## 8. 起動と配布

- `起動.bat`: サーバーを起動し、Edge を全画面（キオスク）で `http://localhost:5100` に開く。`初回セットアップ.bat`: 仮想環境の作成とパッケージの導入。**作った・直した `.bat` は必ず実行して確認する。**
- PC起動時の自動起動、LAN公開（ファイアウォール設定）は、必要になった時点で `lan-webapp-serve` スキルの手順で追加する。

## 9. テストと確認

- **自動テスト（pytest）**: 前日の内容の引き継ぎ（休日またぎ・全削除後に再コピーしない）、行の削除で詰める・▲▼の入れ替え、会社による責任者の絞り込み、今週（月〜日）の判定と月曜でのリセット、休日の判定（土日・祝日・会社の休日）、ファイル名からのジャンル判定（`＋`・未登録ジャンル）、CSVが壊れているときの動作。
- **実機確認（実際にブラウザで開く）**: 入力・スクロール・自動再生・編集ロック・待機画面・文書ボタン。フルHDと4Kの表示、タッチ操作（実機）。
- 画面を変えたらブラウザで開いて確認する。実行できないものは「未検証」と明記する。
